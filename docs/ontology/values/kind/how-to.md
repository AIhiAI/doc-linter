# Kind: how-to

Diátaxis: **task-oriented**. The reader has a problem in mind and
needs the steps to solve it. They already know what tools they have;
they just need the procedure.

## When to write a how-to

- A runbook for an operational task
- A recipe for a recurring workflow
- A "how do I X?" answer for one specific X

## How-to vs reference

How-to = "Here's the procedure for THIS task." Linear.

Reference = "Here's the complete catalog of options." Lookup.

If the doc lists every flag a tool accepts, it's a reference. If it
walks through one specific use of the tool, it's a how-to.

## Convention

- Lead with the goal (one line)
- Numbered steps, copy-pasteable commands
- Note prerequisites at the top, not inline
- Skip explanation/theory — link to a [[value-kind-explanation]]
  doc instead
